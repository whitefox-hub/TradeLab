Risk limits

What the engine refuses, and what it has refused.

LimitIn forceWhat it stops On breach

Read, never set. A risk limit defines behaviour, so §12.4 keeps it out of the operator's editable settings — changing one creates a new configuration and a run records which it ran under, so a limit is never edited beneath a position that was opened under it. The engine evaluates these independently of the strategy and counts positions from observed fills, never from what the strategy reports: a strategy that miscounts its own state is the case these exist for.

Every breach the engine can raise

Three of these are not a configured number. halted is a halt already in force, below_min_viable is a position too small to be worth its costs, and event_context is the one case where an order is allowed and carries a breach — news cutting the size down rather than refusing it. Anywhere that checks only for a breach would read that as a refusal, which is why it has a name.
