Touching any of these creates a new strategy — a new id and code hash — which returns to screening and adds its trials to the counter that deflates every later result. That is not a policy the interface enforces; a run's parameters are immutable in the schema, so modifying one produces a different run and never an edit.

    Adjusting a signal parameter because of what the simulator showed is the trap §12.4 exists to name: after three or four iterations the strategy is fitted to the last few weeks of market, overfitted exactly as in a backtest, only slower and more convincing because it looks live. What is legitimate to conclude from a simulator run is that the strategy does not work. Rejecting is free; re-tuning costs the whole validation.
